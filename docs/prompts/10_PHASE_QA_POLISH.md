# فاز ۱۰ — کیفیت، دسترس‌پذیری، تست E2E، اسکرین‌شات، مستندات

## کار
1. **بازبینی UI/UX:** همه صفحات را در fa/en، روشن/تیره، ۳۹۰px/۱۴۴۰px/۱۹۲۰px مرور کن؛ هم‌ترازی RTL (آیکون‌های جهت‌دار با `rtl:rotate-180`)، اعداد tabular، حالت‌های خالی/بارگذاری/خطا، فوکوس کیبورد، کنتراست. هیچ متن انگلیسی ترجمه‌نشده در fa.
2. **عملکرد:** `dynamic import` برای three.js و zxing؛ memo کامپوننت‌های سنگین؛ محدود کردن طول لاگ زنده.
3. **تست‌ها:**
   - vitest: همه قواعد دامنه (فازهای قبل) + `guidanceFor` + KPIها با داده ناکافی → null.
   - Playwright (`web/e2e/`): (الف) smoke — همه routeها در fa و en باز شوند، بدون خطای کنسول؛ (ب) E2E — سناریوی S-NORMAL در حالت دستی: دروازه تأیید → وزن اول → وزن دوم → نهایی‌سازی → مجوز خروج → اسکن (ورود دستی کد) در `/app/guard` → پذیرفته → اسکن دوم → رد؛ (ج) اسکرین‌شات تمام‌صفحه همه صفحات در `docs/screenshots/` (موبایل برای `/d/*` و `/app/guard`، ۱۹۲۰ برای `/display/*`).
4. **مستندات:** `README.md` ریشه (معرفی، اجرای `cd web && npm i && npm run dev`، نقشه صفحات با لینک، سناریوهای دمو، معماری، محدودیت‌ها: همه سخت‌افزار شبیه‌سازی است، مسیر تبدیل به محصول واقعی: Postgres، Edge agent واقعی برای indicator RS-232، درایور ANPR/RFID، PLC با interlock سخت‌افزاری، احراز هویت واقعی).
5. `docs/DEMO_SCRIPT.md`: سناریوی ارائه ۱۰ دقیقه‌ای قدم‌به‌قدم (کدام صفحه، کدام سناریو، چه چیزی نشان داده شود).
